# Phase 02 Plan 03: Difficulty Selector + Track Parameterization

## Goal

Three difficulty buttons (FÁCIL / MÉDIO / DIFÍCIL) appear on the menu with a persistent selected state; pressing INICIAR passes the chosen difficulty to `game.start()`, which correctly limits obstacle count and sets speed multiplier for the run.

## Tasks

### T1: Add difficulty buttons to `index.html` and style in `style.css`

**Files:** `index.html`, `style.css`

**What:** Insert three difficulty buttons inside `#menu .overlay-inner` (between the record line and the INICIAR button) and add CSS for their layout and selected state.

**How — `index.html`:**

1. Inside `#menu > .overlay-inner`, add a difficulty container div immediately before `<button id="btnIniciar">`:

   ```
   <div id="difficultySelector" class="difficulty-selector">
     <button class="difficulty-btn" data-difficulty="facil" type="button">FÁCIL</button>
     <button class="difficulty-btn selected" data-difficulty="medio" type="button">MÉDIO</button>
     <button class="difficulty-btn" data-difficulty="dificil" type="button">DIFÍCIL</button>
   </div>
   ```

   The `data-difficulty` values are `facil`, `medio`, `dificil` (no accents — used as JS keys). MÉDIO has `class="difficulty-btn selected"` to show the default selection (D-07: default is Médio).

**How — `style.css`:**

1. Add `.difficulty-selector` rule:
   - `display: flex`
   - `gap: 12px`
   - `flex-wrap: wrap`
   - `justify-content: center`

2. Add `.difficulty-btn` rule:
   - `background: transparent`
   - `color: #00ffff`
   - `border: 2px solid #00ffff`
   - `padding: 12px 20px`
   - `font-family: 'Press Start 2P', monospace`
   - `font-size: 12px`
   - `cursor: pointer`
   - `touch-action: none`
   - `min-width: 80px`
   - `min-height: 60px`
   - `letter-spacing: 1px`
   - `-webkit-tap-highlight-color: transparent`

3. Add `.difficulty-btn.selected` rule:
   - `background: #00ffff`
   - `color: #1a0033`
   - `border-color: #00ffff`
   - `box-shadow: 0 0 10px #00ffff`

4. Add `.difficulty-btn:active { transform: scale(0.93); }` for press feedback.

**Verify:** Open the page. The menu must show three buttons in a row: FÁCIL, MÉDIO (highlighted/selected), DIFÍCIL. Tapping a button must visually highlight it (full background fill) and un-highlight the others.

### T2: Wire difficulty selection in `main.js` + update `game.start()` call

**Files:** `main.js`

**What:** Track the selected difficulty in `main.js`; pass the correct `{ speedMultiplier, obstacleCount }` to `game.start()` when INICIAR is pressed. Use `pointerup` on difficulty buttons, toggle `.selected` class in JS.

**How:**

1. In `main.js`, after getting the DOM refs from Plan 02, add:

   ```
   const difficultyBtns = document.querySelectorAll('.difficulty-btn');
   ```

2. Define the difficulty config map:

   ```
   const DIFFICULTY_CONFIG = {
     facil:   { speedMultiplier: 0.75, obstacleCount: 6  },
     medio:   { speedMultiplier: 1.0,  obstacleCount: 8  },
     dificil: { speedMultiplier: 1.4,  obstacleCount: 12 },
   };
   ```

   These values match D-07 exactly.

3. Initialize `let selectedDifficulty = 'medio';` (default per D-07).

4. For each difficulty button, add a `pointerup` listener:
   - Remove `.selected` class from all `.difficulty-btn` elements.
   - Add `.selected` to the tapped button.
   - Set `selectedDifficulty = btn.dataset.difficulty`.

5. Update the INICIAR `pointerup` listener (added in Plan 02) to pass `DIFFICULTY_CONFIG[selectedDifficulty]` instead of the hardcoded `{ speedMultiplier: 1.0, obstacleCount: 8 }`:
   ```
   game.start(DIFFICULTY_CONFIG[selectedDifficulty]);
   ```

6. Also wire `returnToMenu()` to restore the difficulty selector to the previously selected button when the menu reappears. Because `selectedDifficulty` persists in `main.js` scope across runs and the `.selected` class is never removed at `returnToMenu()` time, this is automatic — no extra code needed.

**Verify:** Select FÁCIL, press INICIAR — game starts, fewer obstacles visible at slower speed. Retry to menu, select DIFÍCIL, press INICIAR — noticably more obstacles and faster speed. Verify by watching obstacle density and scroll speed in the first 10 seconds.

### T3: Parameterize `Track.js` obstacle pool to support difficulty (max-pool + active limit)

**Files:** `game/Track.js`, `game/Game.js`

**What:** Track always builds a pool of 12 bodies (max for Difícil). A `setDifficulty(obstacleCount)` method sets `this._activeLimit`, which caps active spawning. `game.start()` calls `track.setDifficulty()` before `track.reset()`. The module-level `OBSTACLE_COUNT` constant is no longer used in the pool loop.

**How — `game/Track.js`:**

1. Change `_buildObstaclePool()`: replace `for (let i = 0; i < OBSTACLE_COUNT; i++)` with `for (let i = 0; i < 12; i++)`. The pool always builds 12 bodies regardless of difficulty. Keep the `const OBSTACLE_COUNT = 8` line as documentation but do not use it in the loop.

2. Add `this._activeLimit = 8;` to the constructor (default = Médio, matching the previous hardcoded behaviour).

3. Add a public method `setDifficulty(obstacleCount)` that sets `this._activeLimit = obstacleCount`.

4. In `_trySpawnObstacle()`, change the pool-exhaustion check. Currently: `const obs = this._obstacles.find((o) => !o.active); if (!obs) return;`. Change to:
   - First count active obstacles: `const activeCount = this._obstacles.filter(o => o.active).length;`
   - If `activeCount >= this._activeLimit` return early (difficulty cap reached).
   - Then find an inactive slot: `const obs = this._obstacles.find(o => !o.active); if (!obs) return;`
   - This ensures: (a) we never exceed the difficulty's active limit, (b) we still guard against pool exhaustion as a safety net.

**How — `game/Game.js`:**

1. In `start({ speedMultiplier = 1.0, obstacleCount = 8 } = {})`, add these calls before starting the RAF:
   - `this.track.setDifficulty(obstacleCount);`
   - `this.track.reset();`
   - `this.car.reset();`
   - `this.score = 0;`
   - `this._lastTime = performance.now();`

   Currently `start()` only sets `_lastTime` and starts RAF — it does not reset game state. Now it must reset before each run (per RESEARCH §2 ordering).

2. Remove the `reset()` call chain from `returnToMenu()` context (it was never there, just confirming: `returnToMenu()` does NOT call `track.reset()` or `car.reset()` — those happen in `start()`).

**Verify:**
- Open DevTools, set breakpoint at `_trySpawnObstacle`. Select FÁCIL, start game — verify `this._activeLimit` is `6`. Select DIFÍCIL, start game — verify `this._activeLimit` is `12` and more than 8 obstacles appear simultaneously on screen.
- The game must not throw after switching difficulty between runs.
