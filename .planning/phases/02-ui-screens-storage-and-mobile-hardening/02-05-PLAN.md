# Phase 02 Plan 05: WebGL Context Loss Handler

## Goal

On Android when the WebGL context is lost (e.g., switching apps), a "TOQUE PARA RECARREGAR" overlay appears instead of a blank canvas; if the browser automatically restores the context, the overlay disappears and the game resumes; if not, tapping the overlay reloads the page.

## Tasks

### T1: Add context-loss overlay to `index.html` and `style.css`

**Files:** `index.html`, `style.css`

**What:** Add a `#contextLoss` overlay div that starts hidden; add CSS that places it above all other overlays (including game-over at z-index 100).

**How — `index.html`:**

1. Add the following div as the last element before `</body>` (after the game-over overlay and the script tag — but before `</body>`). It must be the last overlay declared so stacking context is correct:

   ```html
   <div id="contextLoss" class="overlay hidden" aria-hidden="true">
     <div class="overlay-inner">
       <p class="ctx-loss-msg">TOQUE PARA RECARREGAR</p>
     </div>
   </div>
   ```

   The div starts hidden. It is revealed by the `webglcontextlost` handler.

**How — `style.css`:**

1. Add `#contextLoss` rule that overrides the default `.overlay` z-index:
   - `z-index: 200` — above `.overlay` (z-index: 100) and touch controls (z-index: 75)
   - `cursor: pointer` — indicates tappability
   - `pointer-events: auto` — ensures taps on the overlay work (already true from `.overlay` rule but be explicit)

2. Add `.ctx-loss-msg` rule:
   - `margin: 0`
   - `color: #ffee00`
   - `font-size: clamp(14px, 4vw, 22px)`
   - `text-shadow: 0 0 12px #ffee00`
   - `text-align: center`

**Verify:** Temporarily remove `.hidden` from `#contextLoss` in HTML, open the page — the overlay must appear on top of everything else. Restore `.hidden` before proceeding to T2.

### T2: Register `webglcontextlost` and `webglcontextrestored` listeners in `Game.js`

**Files:** `game/Game.js`

**What:** After renderer creation in the constructor, register both canvas event listeners. `webglcontextlost` must call `event.preventDefault()` as its literal first statement before any other code. `webglcontextrestored` attempts renderer re-init and hides the overlay; on failure, keeps the overlay and logs the error. Tapping the overlay reloads the page as a universal fallback.

**How:**

1. In the constructor, after `this.renderer.setSize(...)` and before the Scene setup, add DOM ref:
   ```
   this._contextLossEl = document.getElementById('contextLoss');
   ```

2. Register the `webglcontextlost` listener on `this.canvas` (not on `this.renderer`'s domElement — they are the same canvas element here, but be explicit):
   ```
   this.canvas.addEventListener('webglcontextlost', (event) => {
     event.preventDefault();           // MANDATORY — must be the first statement
     this._paused = true;              // stop physics processing in _tick
     this._contextLossEl.classList.remove('hidden');
     this._contextLossEl.setAttribute('aria-hidden', 'false');
   }, false);
   ```
   The `false` third argument specifies the bubbling phase (not capture). `event.preventDefault()` must be the literal first line — no variable declarations, no logging before it.

3. Register the `webglcontextrestored` listener:
   ```
   this.canvas.addEventListener('webglcontextrestored', () => {
     try {
       // Re-upload all GPU resources (programs, buffers, textures) to the restored context
       if (typeof this.renderer.forceContextRestore === 'function') {
         this.renderer.forceContextRestore();
       }
       // Render one frame to verify GPU state is valid before unpausing
       this.renderer.render(this.scene, this.camera.instance);
       // Success path — hide overlay and unpause
       this._contextLossEl.classList.add('hidden');
       this._contextLossEl.setAttribute('aria-hidden', 'true');
       this._paused = false;
       this._lastTime = performance.now(); // prevent delta spike on resume
     } catch (e) {
       // Re-init failed — keep overlay showing so user sees "tap to reload"
       console.error('[RetroRacer] WebGL context restore failed:', e);
     }
   }, false);
   ```
   Note on `forceContextRestore`: This method exists on Three.js WebGLRenderer r152+. The project uses r175 so it should be present, but the `typeof` check guards against unexpected API changes. If absent, the catch block handles it — the overlay stays, user taps to reload.

4. Wire the tap-to-reload fallback on the overlay element itself. Add this immediately after the `webglcontextrestored` listener registration:
   ```
   this._contextLossEl.addEventListener('pointerup', () => {
     window.location.reload();
   });
   ```
   This is the fallback for devices where `webglcontextrestored` never fires (context permanently lost) or where re-init fails. Tapping the overlay always reloads the page.

**Verify:**

**Simulation test** (Chrome DevTools — no Android device needed):
1. Open the game in Chrome. Start a run so the game is in PLAYING state.
2. Open DevTools > Application tab > Storage > right panel shows no relevant option — instead, use the Console:
   ```
   const canvas = document.getElementById('gameCanvas');
   const ext = canvas.getContext('webgl2').getExtension('WEBGL_lose_context');
   ext.loseContext();
   ```
3. The "TOQUE PARA RECARREGAR" overlay must appear immediately.
4. Restore the context:
   ```
   ext.restoreContext();
   ```
5. The overlay must disappear and the game must resume.

**Reload fallback test:**
1. Show the context-loss overlay manually (remove `.hidden` in DevTools Elements panel).
2. Tap / click the overlay — page must reload.

**Non-crash test:**
1. Open the page normally without triggering context loss — game must work exactly as before. The listeners must be invisible in normal operation.
