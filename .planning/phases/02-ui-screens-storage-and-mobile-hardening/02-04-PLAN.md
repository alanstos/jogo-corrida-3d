# Phase 02 Plan 04: Game-Over Revamp + Highscore Persistence + "NOVO RECORDE!" Badge

## Goal

After a collision, the game-over screen shows the run score, displays the all-time record, shows "NOVO RECORDE!" when the score beats the saved best, and both MENU and RETRY buttons return the player to the menu; the best score survives a page refresh and appears on the menu.

## Tasks

### T1: Revamp game-over overlay HTML and add highscore elements

**Files:** `index.html`

**What:** Replace the single `#retryButton` with two buttons (RETRY and MENU, both going to menu); add `#goRecordBadge` and `#goHighScoreValue` elements inside `#gameOver .overlay-inner`.

**How:**

1. Replace the entire `<div id="gameOver" ...>` block with:

   ```html
   <div id="gameOver" class="overlay hidden" aria-hidden="true">
     <div class="overlay-inner">
       <h1 class="go-title">GAME OVER</h1>
       <p class="go-score">SCORE: <span id="goScoreValue">0</span></p>
       <p id="goRecordBadge" class="go-record-badge hidden">NOVO RECORDE!</p>
       <p class="go-highscore">RECORDE: <span id="goHighScoreValue">0</span></p>
       <div class="go-buttons">
         <button id="retryButton" type="button">RETRY</button>
         <button id="menuButton" type="button">MENU</button>
       </div>
     </div>
   </div>
   ```

   Notes:
   - `#goRecordBadge` starts hidden (`.hidden` class) — revealed conditionally per D-05.
   - `#goHighScoreValue` shows the persisted record for comparison (not the current run score).
   - Two separate buttons: `#retryButton` (labeled "RETRY") and `#menuButton` (labeled "MENU"). Both trigger `returnToMenu()` per D-04.
   - `.go-buttons` wrapper needed for horizontal layout of the two buttons.

### T3: Wire highscore logic in `game/Game.js`

**Files:** `game/Game.js`

**What:** Import `safeGet` / `safeSet` from `Storage.js`. Initialize `this._highScore` in the constructor. On collision, compute `isNewRecord`, conditionally write localStorage and show badge, update `#goHighScoreValue`. Add DOM refs for new elements. Wire `#menuButton` to `returnToMenu()`. Update the menu's RECORD display when `returnToMenu()` is called.

**How:**

1. At the top of `Game.js`, add the import:
   ```
   import { safeGet, safeSet } from './Storage.js';
   ```

2. In the constructor, after the DOM refs section, add:
   ```
   this._highScore = safeGet('melhorPontuacao', 0);
   ```
   This loads the saved record once on page load.

3. Add DOM refs in the constructor:
   - `this._goRecordBadgeEl = document.getElementById('goRecordBadge');`
   - `this._goHighScoreEl = document.getElementById('goHighScoreValue');`
   - `this._menuBtn = document.getElementById('menuButton');`
   - `this._menuRecordEl = document.getElementById('menuRecord');` — the record `<p>` in the menu overlay (added in Plan 02)
   - `this._menuRecordValueEl = document.getElementById('menuRecordValue');`

4. Wire `#menuButton` with `pointerup`:
   ```
   if (this._menuBtn) {
     this._menuBtn.addEventListener('pointerup', () => this.returnToMenu());
   }
   ```

5. Also update the existing `#retryButton` listener to call `this.returnToMenu()` instead of `this.reset()`. Locate the current listener added in Plan 02 (it was updated there to call `returnToMenu()` — confirm it is correct; if not, fix it here).

6. Replace the body of `_handleCarCollision()` with the following logic when `event.body.userData.tag === 'obstacle'`:
   a. `this.state = 'GAME_OVER';` — stops physics path on next tick.
   b. `const finalScore = Math.floor(this.score);`
   c. `const isNewRecord = finalScore > this._highScore;`
   d. If `isNewRecord`: `this._highScore = finalScore; safeSet('melhorPontuacao', finalScore);` — write BEFORE showing overlay (RESEARCH pitfall #9).
   e. `this._goScoreEl.textContent = String(finalScore);`
   f. `this._goHighScoreEl.textContent = String(this._highScore);`
   g. `this._goRecordBadgeEl.classList.toggle('hidden', !isNewRecord);` — shows badge only when new record.
   h. `this._gameOverEl.classList.remove('hidden'); this._gameOverEl.setAttribute('aria-hidden', 'false');`

7. In `returnToMenu()` (added in Plan 02), add after hiding the game-over overlay:
   - Update the menu record display:
     ```
     this._menuRecordValueEl.textContent = String(this._highScore);
     if (this._highScore > 0) {
       this._menuRecordEl.classList.remove('hidden');
     }
     ```
   - This reveals the `RECORDE:` line on the menu once a score exists (D-06).

**Verify:**

1. Complete a run (hit an obstacle). Game-over overlay appears with: run score, record score, and two buttons (RETRY + MENU).
2. If it is the first run ever, "NOVO RECORDE!" badge appears (score > 0 > saved default of 0 — first score always beats 0). The `RECORDE:` value on the overlay shows the just-saved score.
3. Press MENU — returns to menu. `RECORDE: <score>` line is now visible on the menu.
4. Refresh the page — menu shows `RECORDE: <same score>` (loaded from localStorage).
5. Complete a second run with a lower score — "NOVO RECORDE!" badge does NOT appear. Game-over shows current score and the higher saved record separately.
6. Complete a third run beating the record — "NOVO RECORDE!" badge appears, record line updates.
