<objective>
Implement collision-burst particles (FEEL-02): every time the player's car collides with an obstacle, a burst of orange particles appears at the impact point and dissipates over ~0.6 seconds. The system uses a pre-allocated InstancedMesh pool of 20 particles backed by MeshBasicMaterial — one draw call, zero per-frame allocation, no PBR cost. Visual feedback at the moment of failure is what makes the game feel like an arcade game rather than a tech demo.

Purpose: Without particles, collisions are silent and abrupt — the game-over overlay appears with no kinetic confirmation that something just happened. The particle burst also primes the camera shake (Plan 03-04) and haptic (Plan 03-05) which both fire at the same collision event; particles are the visual half of that multi-modal feedback.

Output: New module game/ParticleSystem.js implementing the pool with burst/update/reset; Game.js extended to construct, drive, and reset the particle system at the correct loop slots.
</objective>

  <action>
    Create the new file `game/ParticleSystem.js`. The module follows the existing project conventions: default class export, `import * as THREE from 'three'` only (no cannon-es), constructor takes a single `scene` argument and adds the mesh to it.

    Module-level constants (declared after imports, before the class):
    - `MAX_PARTICLES = 20` — pool size; the hard ceiling from FEEL-02 requirement
    - `BURST_COUNT = 8` — particles activated per burst call (leaves headroom for overlapping bursts; FEEL-02 allows up to 20)
    - `PARTICLE_LIFETIME = 0.6` — seconds before a particle expires
    - `PARTICLE_SPEED = 8` — initial speed in world units per second
    - Particle color constant `0xff8800` (orange — chosen per RESEARCH Open Question #2 for contrast against cyan car and purple road)

    Class structure — `export default class ParticleSystem`:

    **constructor(scene)**:
    1. Store `this._scene = scene`.
    2. Pre-allocate reusable THREE objects so burst() and update() never call `new`:
       - `this._dummy = new THREE.Object3D()` — for composing matrices
       - `this._zeroScale = new THREE.Matrix4().makeScale(0, 0, 0)` — to hide inactive instances
       - `this._tmpPos = new THREE.Vector3()` — scratch for reading back instance positions in update()
       - `this._tmpQuat = new THREE.Quaternion()` — scratch for matrix decompose
       - `this._tmpScale = new THREE.Vector3()` — scratch for matrix decompose
    3. Create one shared `THREE.BoxGeometry(0.15, 0.15, 0.15)` (small cube — retro arcade visual).
    4. Create one shared `THREE.MeshBasicMaterial({ color: 0xff8800 })`. NOT MeshLambertMaterial, NOT MeshStandardMaterial — particles need no lighting calculation.
    5. Create `this._mesh = new THREE.InstancedMesh(geometry, material, MAX_PARTICLES)`. Set `this._mesh.frustumCulled = false` — particles may briefly travel near the camera edge where frustum culling could pop the whole instanced mesh off.
    6. Allocate `this._particles = []` — an array of MAX_PARTICLES state objects. Each entry: `{ velocity: new THREE.Vector3(), lifetime: 0, active: false }`. The Vector3 is pre-allocated here so per-burst velocity randomization mutates an existing object instead of allocating.
    7. Loop `i` from 0 to MAX_PARTICLES-1:
       - `this._mesh.setMatrixAt(i, this._zeroScale)` — start all instances hidden
       - Push a particle state object to `this._particles`
    8. Set `this._mesh.instanceMatrix.needsUpdate = true` — initial hidden state must flush to GPU.
    9. `scene.add(this._mesh)`.

    **burst(position)** — `position` is expected to be a THREE.Vector3 (world-space impact point):
    1. Iterate `i` from 0 to MAX_PARTICLES-1, counting activations in a local `activated` variable.
    2. Skip if `this._particles[i].active === true`.
    3. For each inactive slot found, up to BURST_COUNT:
       - Set `p.active = true`, `p.lifetime = PARTICLE_LIFETIME`.
       - Randomize direction in-place: `p.velocity.randomDirection().multiplyScalar(PARTICLE_SPEED)`. (Vector3.randomDirection mutates the vector — no allocation.)
       - Configure `this._dummy.position.copy(position)`, `this._dummy.scale.set(1, 1, 1)`, `this._dummy.rotation.set(0, 0, 0)`, then `this._dummy.updateMatrix()`.
       - `this._mesh.setMatrixAt(i, this._dummy.matrix)` — write the spawn pose.
       - Increment `activated`. Break the loop if `activated >= BURST_COUNT`.
    4. After the loop, set `this._mesh.instanceMatrix.needsUpdate = true` exactly once (not once per particle).

    If all 20 slots are active when burst() is called (an extreme overlap of two collisions within 0.6s), the burst silently activates 0 new particles — this is acceptable arcade behavior (the in-flight particles from the prior burst still convey the impact).

    **update(deltaTime)**:
    1. Initialize a local `anyChanged = false` flag.
    2. Loop `i` from 0 to MAX_PARTICLES-1:
       - If `!this._particles[i].active`, continue.
       - `p.lifetime -= deltaTime`.
       - If `p.lifetime <= 0`: set `p.active = false`, write `this._zeroScale` matrix at slot i, `anyChanged = true`, continue.
       - Otherwise: read the current matrix back via `this._mesh.getMatrixAt(i, this._dummy.matrix)`. Decompose into `this._tmpPos`, `this._tmpQuat`, `this._tmpScale` — these pre-allocated scratch objects avoid a per-frame new Vector3.
       - Advance position: `this._tmpPos.addScaledVector(p.velocity, deltaTime)`.
       - Apply slight gravity to velocity-y: `p.velocity.y -= 9.8 * deltaTime * 0.3` — the 0.3 factor softens gravity for arcade feel.
       - Shrink scale over lifetime: `const s = p.lifetime / PARTICLE_LIFETIME; this._tmpScale.set(s, s, s)`.
       - Recompose: `this._dummy.matrix.compose(this._tmpPos, this._tmpQuat, this._tmpScale)`.
       - `this._mesh.setMatrixAt(i, this._dummy.matrix)`.
       - `anyChanged = true`.
    3. If `anyChanged`, set `this._mesh.instanceMatrix.needsUpdate = true`. Skipping the needsUpdate flag when nothing changed saves a GPU upload during the 99% of frames when no particles are active.

    **reset()**:
    1. Loop `i` from 0 to MAX_PARTICLES-1:
       - `this._particles[i].active = false`
       - `this._particles[i].lifetime = 0`
       - `this._particles[i].velocity.set(0, 0, 0)`
       - `this._mesh.setMatrixAt(i, this._zeroScale)`
    2. Set `this._mesh.instanceMatrix.needsUpdate = true`.

    The class must NOT export any other method or symbol. No init(), no getCount(), no dispose() — keep the surface minimal. The default export is the class itself.

    Hard constraints from CLAUDE.md and RESEARCH:
    - Material MUST be MeshBasicMaterial (not Lambert, not Standard, not Toon).
    - Geometry MUST be reused (single BoxGeometry instance shared by all 20 InstancedMesh slots).
    - burst() and update() must contain ZERO `new THREE.*()` calls — confirm by grep before finishing the task.
