# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-05-27
**Phases:** 1–2
**Total Plans:** 8

## Overview

RetroRacer 3D v1.0 foi construído do zero com planejamento GSD completo após bugs irrecuperáveis de física na implementação anterior. O milestone entrega um jogo de corrida 3D arcade totalmente jogável no browser — carro com física coerente, controles touch, pista infinita, seletor de dificuldade, highscore persistido e proteção contra perda de contexto WebGL.

## Phases

### Phase 1: Physics Foundation and Core Gameplay Loop

**Goal**: Um jogador abre o jogo num browser mobile, o carro avança e vira com toque, obstáculos aparecem na pista, uma colisão termina a corrida com tela de game over, e Retry reseta o jogo em < 500ms sem reload de página
**Depends on**: Nenhuma (primeira fase)
**Plans**: 3 planos

Plans:
- [x] 01-01: PhysicsWorld + ground plane + Car body + Game RAF loop (hard gate: carro move no input)
- [x] 01-02: Track segment pool + obstacles + lateral limits + progressive speed + chase camera + collision/game-over
- [x] 01-03: HUD DOM overlay + touch controls + keyboard fallback + PERF renderer config + visibilitychange pause

**Details:**

Quatro causas simultâneas do bug anterior corrigidas em 01-01: `allowSleep: true`, `applyForce` em world space, `mass: 0`, `syncMesh` antes de `world.step()`. Loop de física com ordem estrita: applyInput → step → syncMesh → render. Track usa SEGMENT_COUNT=12 pool reciclado por z-position relativa ao carro (carZ) — evita bug de reciclagem que quebrava em score ~120. HUD com Press Start 2P e change-detection para evitar DOM writes desnecessários. Controles via Pointer Events API com multi-touch.

---

### Phase 2: UI Screens, Storage, and Mobile Hardening

**Goal**: Jogadores chegam ao jogo por um menu que permite escolher dificuldade, a dificuldade afeta visivelmente densidade de obstáculos e velocidade, o melhor score persiste e é exibido no menu após cada sessão; o jogo sobrevive a perda de contexto WebGL e troca de app sem crashar
**Depends on**: Phase 1
**Plans**: 5 planos

Plans:
- [x] 02-01: Storage module (safeGet/safeSet com localStorage error-wrapping)
- [x] 02-02: Menu overlay + INICIAR wiring + HUD/Touch hidden on load + returnToMenu()
- [x] 02-03: Difficulty selector (FÁCIL/MÉDIO/DIFÍCIL) + Track obstacle-pool parameterization
- [x] 02-04: Game-over revamp — NOVO RECORDE badge, highscore persistence, RETRY + MENU buttons
- [x] 02-05: WebGL context loss handler — TOQUE PARA RECARREGAR overlay + context restore

**Details:**

Storage.js com null-check explícito e QuotaExceededError silenciado. DIFFICULTY_CONFIG map com speedMultiplier (0.75/1.0/1.4) e obstacleCount (6/9/12). Pool fixo de 12 corpos em Track — sem reconstrução entre runs. safeSet chamado antes de classList.remove('hidden') no game-over para garantir persistência. event.preventDefault() como primeiro statement em webglcontextlost — sem isso, recovery não funciona.

## Milestone Summary

**Key Decisions:**

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Rebuild do zero vs. continuar | Bugs irrecuperáveis de física no código anterior | ✓ Correto — rebuild levou ~4 dias com GSD |
| Manter Three.js + Cannon-es | Stack funcionou; problema era implementação, não as libs | ✓ Confirmado |
| allowSleep: false + applyLocalForce | Duas das quatro causas do bug anterior | ✓ Resolvido em 01-01 |
| Track recycling por carZ relativo | Fixed-threshold quebrava em score ~120 | ✓ Resolvido em 01-03 |
| Pool fixo 12 + _activeLimit cap | Separa construção de pool da regra de spawn ativo | ✓ Padrão estabelecido |
| safeSet antes de mostrar overlay | Evita estado inconsistente se UI falhar | ✓ Padrão de persistência |
| event.preventDefault() primeiro em contextlost | Sem isso, recovery WebGL não funciona | ✓ Crítico para mobile |

**Issues Resolved:**

- Quatro causas simultâneas de carro parado — todas corrigidas em 01-01
- Track recycling com threshold fixo quebrava em score ~120 — corrigido com posição relativa em 01-03
- Context WebGL loss travava o jogo em Android — corrigido com handlers em 02-05

**Issues Deferred:**

- Lap gates / sistema de fases (deferred para v2 — endless/distance-score model adotado)
- Fase 2 — Autodromo Arcade (v2)
- Fase 3 — Rodovia Infinita (v2)

**Technical Debt Incurred:**

- `console.log` periódico de posição do carro em `Game.js` L276 — debug artifact de Phase 1, emite ~1 log/segundo em produção. Remoção recomendada em próximo cleanup.
